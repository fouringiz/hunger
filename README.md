# Ultimate Tower Defense

Мобильный sci-fi tower defense. Актуальный паспорт — **v2.13**, прототип — **v0.8**.

**v0.8 — Огнемёт (числа черновые):** четвёртая линейка башен. Бьёт струёй горящего топлива и водит ею в пределах четверти круга (±45° от цели); всё, чего коснулась струя, горит ещё 2,5 секунды, повторное касание обновляет горение, но не складывает. Панцирник в струе закрывает 65% огня тем, кто за ним. Дальность короткая (95). На 4-м уровне: Плазма — топливо горит лужами на тропе, до трёх луж на башню; Криоструя — хладагент замедляет на 45% и почти не жжёт. Против огня у роя мутация Зеркальный хитин (−30% огненного урона).

**v0.7.1:** плановую мутацию больше нельзя обойти рывком. Если вызвать волну поверх ещё не закрытой волны с плановой эволюцией (4-й или 8-й), её мутация решается в момент вызова — по урону, накопленному к этому моменту, — и достаётся вызванной волне; второй раз при закрытии она не срабатывает. Без нахлёста ничего не меняется. Реплеи подписываются версией `prototype-v0.7`.

**v0.7 — волны внахлёст:** следующую волну можно вызвать в любой момент, в том числе во время боя; можно накликать все десять. Досрочный вызов приносит 3 кредита за каждую сэкономленную секунду паузы, вызов поверх идущей волны — за целую паузу (60). Первый вызов поверх живой волны даёт рою одну дополнительную мутацию из тех, что у него ещё нет, — один раз за партию, сверх двух плановых; выбор выглядит случайным, но зависит только от момента вызова, поэтому реплеи его повторяют. Волна заканчивается, когда погибли её собственные враги; победа — когда выпущены все десять волн и поле пусто. Кассета теперь раскрывается в воздухе: один снаряд долетает до точки разрыва, пять бомбочек расходятся, каждая бьёт тремя осколками в пределах своей зоны (только картинка, бой прежний).

**v0.6 — ветки четвёртого уровня (числа черновые):** башня третьего уровня выбирает одну из двух специализаций навсегда; чтобы сменить — продать. Турель: Пулемёт (вдвое чаще, урон ×0.75) или Винтовка (урон ×4, реже, +40 дальности, пуля проходит тень Панцирника). Voltaic: Тесла (+2 прыжка, медленнее затухает) или Призма (без цепи, урон ×3 — громоотводам нечего обрывать). Пушка: Гаубица (урон ×2.2, реже) или Кассета (5 бомбочек по кольцу — против Рассредоточения и рывка). Цены 150 / 170 / 200. Выбор ветки пишется в реплей.

**v0.5 — проход по балансу (числа черновые):** урон турели 7 → 8.5, Voltaic 14 → 17, пушки 45 → 40; рост HP врагов за волну 0.08 → 0.11 (ранние волны почти не меняются, поздние тяжелее). Цель — чтобы ни одна линейка не проходила кампанию в одиночку начисто. Партии v0.4 записаны по старым правилам и проверяются под пресетом `?balance=v04`; инструменты делают это сами.

## Быстрый старт

Откройте [prototype/index.html](prototype/index.html) в браузере. Установка зависимостей и сборка не нужны.

Полевой тест пехоты: добавьте `?infantry=1` к адресу прототипа.
В этом эксперименте доступна Barracks с тремя бойцами ближнего боя; числа черновые.
Обычная партия открывается без этого параметра. [Методика и ограничения](reports/infantry-field-trial.md).

Ранний рисованный референс ползания: `node tools/preview-forager.cjs`, затем `reports/generated/forager-study.html`. Текущий игровой вариант описан ниже.

Новая походка Фуражира подключена в `prototype/index.html`: исходная фактура тела, отдельно движущиеся лапы, контактная грязь и органическая тропа. Крупный просмотр той же игровой отрисовки: `node tools/preview-forager-puppet.cjs`, затем `reports/generated/forager-puppet-study.html`. Другие касты пока используют прежний арт. [Ассеты и ограничения проекции](assets/art/forager-mire-runtime-v1.md).

Локация из арт-прохода #28 подключена к игре: органический грунт по всей карте, подробная жидкая тропа, высокие бетонные платформы, древние Врата с резной каменной архитектурой и складывание оружия при паузе. После визуального ревью тропа получила отдельную текстуру жижи без прежнего уменьшения детализации, а платформы и Врата — отдельный подробный арт. Зелёно-бурая палитра открывается по умолчанию; `?zone=ember` показывает сохранённый красно-жёлтый вариант для другой зоны. Параметр меняет только оформление. [Материалы, проверка и следующий пакет](assets/art/organic-world-runtime-v1.md).

Проверки игровой логики:

```sh
node tests/prototype-regression.cjs
```

## Запись партии

После победы или поражения нажмите **Save replay** — браузер скачает JSON-файл. Прикрепите его к сообщению с наблюдениями о партии. Запись начинается с **DEPLOY**; ранее сыгранные партии восстановить нельзя.

Для просмотра нажмите **Load replay** в стартовом меню и выберите файл. Игра воспроизведёт действия и проверит итог. Несовместимая версия или расхождение показываются явно. Во время повтора управление постройками отключено.

Для тестов и инструментов арта один раз выполните `npm install` (ставит `@napi-rs/canvas` для съёмки кадров и проверки атласов); весь набор тестов — `npm test`. Сама игра по-прежнему открывается без установки.

Проверка без браузера: `node tools/replay-party.cjs путь/к/партии.json`.

Для плейтеста кандидатов баланса есть пресеты, выбираемые только адресной строкой: `prototype/index.html?balance=parityA` (турель 8.5, Voltaic 17, пушка 40, HP врагов ×1.25 — кандидат из `reports/balance-factors-v0.4.md`). Без параметра игра идёт по кампанийным правилам. Пресет виден в HUD, входит в отпечаток правил и записывается в реплей: партии на пресете не смешиваются с эталонными. Пресет удаляется, когда его числа приняты или отвергнуты.

Партии на пресете parity A — отдельный набор `reports/replays/human-v0.4-parityA/`; эталонный набор содержит только партии по кампанийным правилам. Измерения эволюции на обоих наборах: `node tools/replay-sweep.cjs measure` (отчёт `reports/evolution-measures-v0.4.md`).

Записанные партии игрока лежат в `reports/replays/human-v0.4/` и служат эталонными таймлайнами для контрфактных прогонов баланса: `node tools/replay-sweep.cjs` меняет по одному правилу и воспроизводит действия игрока на записанных тиках (политика и верность — в `reports/balance-factors-v0.4.md`).

Полевое испытание пехоты (`prototype/index.html?infantry=1`) видно реплеям: такие партии помечаются `infantryTrial`, несут состояние солдат в подписях и проверяются только в режиме испытания; кампанийный отпечаток правил без испытания прежний. Если изменение кода меняет отпечаток исходника, не меняя поведения кампании, закоммиченные реплеи перештамповываются командой `node tools/restamp-replays.cjs --write` — только после полной сверки состояния каждой партии строгим верификатором.

## Версионирование

Номера паспорта и прототипа независимы: паспорт v2.13 не означает игру v2.13.

| Ветка или метка | Назначение |
| --- | --- |
| `main` | Актуальный проект. Старые паспорта не дублируются в файлах. |
| `design/v…` | Архив: снимки паспортов до v2.12 включительно. С v2.13 снимки не режутся — историю держит git (`git log --follow docs/`), релиз помечается тегом `passport/vX.Y`. |
| `prototype/v0.2` | Снимок выпуска v0.2; `main` содержит v0.4 и последующие исправления (метки v0.3 и v0.4 не ставились). |
| `v0.1` | Исходная ветка до наведения порядка; сохранена для восстановления. |

### Дальнейшая работа

1. Изменения вести в коротких рабочих ветках `codex/<тема>`, затем объединять с `main`.
2. При фиксации нового паспорта обновлять актуальный документ в `main` и ставить тег `passport/vX.Y` на коммит релиза. Старые снимки `design/v…` не менять.
3. При выпуске прототипа запускать проверки и создавать новую метку `prototype/vX.Y`. Существующие метки не переносить.

Проверки покрывают движение Пиявки, генераторы, таргетинг, занятость слотов, расписание фоновой эволюции (момент, выбор по счёту урона, лимит стака, перенос на следующую волну) и одинаковый ход боя при разной частоте кадров и скорости игры. Итоговое число сценариев видно при запуске тестов. Они не заменяют визуальный плейтест и проверку баланса.

Симуляция всегда рассчитывается шагами по 1/60 с; частота кадров и переключатель ×2 меняют число шагов за кадр. После долгой остановки вкладки обрабатывается не более 0.25 с реального времени за кадр, чтобы возвращение в игру не вызвало скачок на несколько волн.

Воспроизводимые исследования:

```sh
node tools/check-balance.cjs
node tools/check-evolution-response.cjs
node tools/check-mutation.cjs
node tools/sweep-sprinter.cjs
```

Результаты сохраняются в `reports/generated/` и не включаются в Git. Контроль эволюции сравнивает новую Турель с обычными улучшениями и собирает страницу давления HP ×1.5 для плейтеста; перебор Sprinter сохраняет отклонённый эксперимент как исследовательский инструмент.
