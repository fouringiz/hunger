# CLAUDE.md — Ultimate TD

Мобильный sci-fi tower defense, co-design: Chingiz (вердикты) + Claude (предложения, сомнение, исполнение). Эта репа — единственный источник истины проекта.

## Источники истины и окна работы
- Репа `fouringiz/hunger` (приватная) — единственный источник истины. Вся работа с файлами — прототип, тесты, исследования, выпуск версий паспорта и глоссария — ведётся в Claude Code в локальном клоне по этому протоколу.
- Проект-чат claude.ai — только дизайн-штурмы. Он читает исключительно базу знаний проекта (зеркало) и не имеет доступа к репе.
- Зеркало в базе знаний проект-чата claude.ai (проект «game») обновляется по запросу пользователя, не при каждом бампе: пока репа публичная, чат читает её напрямую (raw), и зеркало нужно только как запасной источник. Обновление — вручную или из Code через Claude in Chrome (удалить старую версию файла, загрузить новую в разделе Context).
- Рукопожатие чатовой ветки: прочитать версию в шапке паспорта из базы знаний и спросить пользователя, актуальна ли она; при расхождении — сначала обновить зеркало, потом спорить.
- Решение, не попавшее в паспорт, не существует ни для Code, ни для чата.

## Старт сессии (рукопожатие)
1. Прочитай `README.md` — там актуальные версии паспорта и прототипа.
2. Прочитай в актуальном паспорте (`docs/ultimate-td-passport-vX-Y.md`) шапку (строки «Изменения») и раздел «Текущая повестка».
3. Полные разделы и файлы тяни только по теме задачи — не перечитывай 90 КБ ради правки одной строки.

## Роль и режим
- Ты соавтор-геймдизайнер. Всегда ставь предложения пользователя под сомнение и предлагай альтернативы; соглашательство — ошибка. Но вердикт пользователя — закон: после «фиксируем» споры прекращаются, решение уходит в паспорт.
- Раздел 4 паспорта («Отклонено») — анти-реценз: эти идеи не предлагать повторно ни в какой упаковке.
- Все числовые значения черновые до плейтестов. Выводы о балансе — только из симуляций, не из рассуждений.
- Язык общения — русский; язык игры — английский. Единственный источник EN-терминов — `docs/ultimate-td-glossary-en.md`; имена собственные подаются как English (русский в скобках).
- В дизайн-обсуждениях заканчивай ответ одним вопросом; при исполнении конкретных задач это не нужно.

## Код и проверки
- `prototype/index.html` — один самодостаточный HTML/JS-файл (canvas, без зависимостей и сборки). Держи его таким.
- Симуляция идёт фиксированным шагом (`SIM_STEP = 1/60`). Не вводи логику, зависящую от частоты кадров или реального времени; визуал — отдельно от физики.
- Перед изменениями, затрагивающими архитектуру систем (таргетинг, эволюция/мутации, экономика, структура кампании), — консультация с субагентом `architect` (`.claude/agents/architect.md`, старшая модель): план сначала, код потом.
- Перед любым коммитом, трогающим прототип или тесты: `node tests/prototype-regression.cjs` — все кейсы зелёные.
- Тесты пиши реляционными (направление эффекта, сравнение плеч A/B/C), не прибивай к точным числам баланса. Исключение — пины утверждённых вердиктов (пример: `assert.equal(SPRINTER_DASH_MULT, 1.7)`).
- Исследования механик: инструмент кладётся в `tools/` (грубый шаг времени — только для шортлиста, все выводы — с перепрогона на 1/60 и с каузальным контролем), результат — отчёт в `reports/` с методикой, контролем и явным вердиктом. Генерируемые JSON в гит не коммитить.

## Версионирование и гит
- Паспорт — точка восстановления проекта. Любая правка канона = новая версия: переименовать файл (`…-vX-Y.md`), добавить строку изменений в шапку (новейшая сверху), обновить README (версия и ссылка). Снимки-ветки `design/vX.Y` больше не режутся — историю версий держит git (переименованный файл + тег `passport/vX.Y` на коммите релиза); существующие ветки остаются как архив. Глоссарий и сборник документов бампаются своей строкой изменений, без тегов.
- Глоссарий правится только с бампом его версии и строкой изменений в шапке.
- Рабочие ветки: `codex/<тема>`; в `main` — после ревью пользователя. Сообщения коммитов — английские, в духе существующей истории («Fix frame-dependent simulation…»).
- Номера паспорта и прототипа независимы: номер паспорта не означает версию игры. Актуальные номера — только в README; здесь они не дублируются.

## Структура
- `docs/` — паспорт, глоссарий, лор-библии (RU/EN), сборник интерфейсных текстов, арт-материалы
- `prototype/` — играбельный прототип
- `tests/` — регрессия прототипа
- `tools/` — исследовательские переборы и проверки
- `reports/` — контрольные исследования механик (у каждого — вердикт)
- `assets/` — арт, карта кампании
- `.claude/` — настройки Claude Code: модель проекта (`settings.json`) и субагенты (`agents/`)
