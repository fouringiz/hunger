# Фоновая эволюция без Координатора — эксперимент

Дата: 2026-10-03. **Не канон.** Основной прототип и паспорт v2.10 сохраняют действующие правила.

## Проверяемая гипотеза

Будет ли эволюция создавать полезные решения, если она больше не зависит от побега Координатора? Есть ли преимущество у добавления другого оружия перед обычным улучшением?

## Правила эксперимента

- Coordinator (Координатор) не появляется. Его сопровождение сохранено, включая награды за убийства. Во всех парных сравнениях состав волн одинаков.
- После волн 4 и 8 появляется одна новая мутация; она действует со следующей волны. Расписание **черновое**, выбрано для сопоставления с прежними моментами эволюции.
- Выбор — по реально нанесённому урону с начала партии или предыдущей мутации. Повтор уже активной мутации заменяется второй доступной; максимум две. Это правило двух мутаций прототипа, а не проект полного каталога.
- Marsh сообщает о мутации до начала следующей волны. Межволновое время подготовки сохранено.
- Исследуются три множителя HP всех врагов: 1, 1.5, 2 (**черновые**). Скорость, число врагов, награды, цены и Sprinter Reflex 1.7× сохраняются.
- Игровой код эксперимента находится в `experiments/background-evolution.js` и подключается только к отдельной сгенерированной странице.

## Полные прохождения: 54 прогона

3 множителя HP × 2 режима эволюции × 3 состава обороны × 3 варианта размещения. Алгоритм закупок взят из существующего исследования баланса. Это ограниченная выборка стратегий, не оценка вероятности победы человека.

| HP | Эволюция | Только Турели: победы / чистые | Только Пушки: победы / чистые | Смешанная: победы / чистые |
| --- | --- | --- | --- | --- |
| ×1 | выключена | 3 / 3 | 3 / 3 | 3 / 3 |
| ×1 | фоновая | 3 / 3 | 3 / 3 | 3 / 3 |
| ×1.5 | выключена | 0 / 0 | 3 / 2 | 3 / 3 |
| ×1.5 | фоновая | 0 / 0 | 3 / 2 | 3 / 3 |
| ×2 | выключена | 0 / 0 | 0 / 0 | 3 / 0 |
| ×2 | фоновая | 0 / 0 | 0 / 0 | 2 / 0 |

Каждая ячейка содержит три прохождения. При ×1 все успешные сборки теперь получают две мутации, но продолжают побеждать без повреждений Врат. При ×1.5 Турели погибают до вступления первой мутации в силу. При ×2 моно-сборки также проигрывают до неё. Следовательно, их поражение нельзя приписать эволюции.

## Ответ на первую мутацию: 18 групп

Для каждого моно-состава, размещения и множителя HP проигрываются реальные волны 1–4 с обычной экономикой. Затем из одного и того же состояния сравнивается волна 5 с мутацией и без неё. Девять групп достигают этой точки; остальные девять завершаются поражением раньше.

В общей рамке **до 110 кредитов из заработанного баланса** проверяются: ничего не покупать, улучшить одну существующую башню, добавить башню того же типа или другого типа. Проверяются все свободные слоты и доступные улучшения; превышение имеющегося энергоснабжения запрещено. Генераторы, продажи и сочетания нескольких покупок в этот узкий контроль не входят. Отсутствие доступного варианта означает «не проверен», а не поражение этого варианта. Затраты и энергопотребление сохраняются в JSON.

- **Турели, HP ×1:** без покупок мутация вызывает 7, 4 и 3 прорыва в трёх расстановках; без мутации прорывов нет. Улучшение Турели за 50 кредитов устраняет их во всех трёх. Пушка за 110 в двух доступных по энергии случаях тоже помогает, но преимущества перед улучшением не показывает.
- **Пушки, HP ×1:** первая мутация не вызывает прорывов даже без покупок.
- **Пушки, HP ×1.5:** без покупок мутация вызывает повреждения Врат во всех трёх расстановках. В двух случаях и дополнительная Турель за 60, и улучшение Пушки за 80 полностью устраняют прорыв. Турель дешевле на 20 кредитов, но потребляет дополнительно 10 энергии против 5 у улучшения.
- В третьем случае HP ×1.5 доступного улучшения до 110 кредитов нет. И новая Пушка за 110, и Турель за 60 предотвращают поражение. Это сравнение двух покупок, а не доказательство превосходства над апгрейдом.

Все цены и ограничения бюджета — текущие **черновые** параметры эксперимента. «Добавить другое оружие» здесь означает расширить состав, не продать и заменить существующие башни.

## Вывод

1. Фоновое расписание устраняет зависимость появления мутаций от выживания Координатора.
2. Одного расписания недостаточно, чтобы заставить менять состав обороны: при текущей нагрузке моно-сборки всё ещё проходят чисто.
3. Усиление врагов выявляет различия между сборками ещё до мутаций. Это полезная граница нагрузки, но не доказательство работы адаптации.
4. Найдено локальное преимущество другого оружия по цене, с большей потребностью в энергии. Уникальная необходимость смены состава не подтверждена.

Следующий шаг — пользовательский плейтест варианта ×1.5: понятны ли предупреждения, есть ли время подготовиться и интересны ли решения. После этого можно обсуждать, даёт ли раннее раскрытие мутации через разведчика дополнительную ценность. Сам Координатор, Marked Observer и канон пока не изменены.

## Воспроизведение и игра

```sh
node tools/check-background-evolution.cjs
# Только собрать игровые страницы и проверить экспериментальные правила:
node tools/check-background-evolution.cjs --build-only
```

Результат в `reports/generated/`:

- `background-evolution.html` — обычная прочность врагов;
- `background-evolution-pressure.html` — HP ×1.5, вариант для плейтеста;
- `background-evolution-results.json` — полные прохождения и все проверенные ответы.

HTML открываются напрямую в браузере, без установки зависимостей. Файлы воспроизводимы и игнорируются Git. В меню основной игры лабораторных кнопок нет.
